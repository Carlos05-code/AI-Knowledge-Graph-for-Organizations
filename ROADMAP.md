# Roadmap

Status of the **AI Knowledge Graph for Organizations** platform. Legend: ✅ done ·
🔄 in progress · ⬜ planned.

## Current status

- ✅ Backend API complete (NestJS 11, 16 controllers, ~60 endpoints, WebSocket chat)
- ✅ Databases wired (PostgreSQL 16 + Prisma, Neo4j, Qdrant, OpenSearch BM25 keyword index, Redis cache w/ in-memory fallback)
- ✅ Flutter app shell (login/register, chat w/ citations, hybrid search, graph explorer, profile, admin, documents, connectors, meetings, policies, notifications)
- ✅ CI (GitHub Actions: backend lint/test/build/docker, frontend analyze/build/docker)
- ✅ Docker Compose stack (18 services), Kubernetes manifests; observability stack (Prometheus alerts.yml + provisioned Grafana dashboards + Loki/promtail log shipping + exporters)
- ✅ Tests: 257 unit + 80 e2e + 28 frontend tests, all passing
- ✅ Documentation suite (docs/)

17. ✅ GitHub `syncAll` fixed + two missing-dependency bugs found (2026-09-18) — done: rewrote `GitHubAdapter` to actually sync — `listTree()` fetches the repo's default (or configured) branch and walks it recursively via Octokit's `git.getTree({recursive: '1'})`, `syncAll()` downloads each blob's raw content (base64-decoded via `repos.getContent`), skips binaries via the same null-byte heuristic every other adapter uses, and populates `SyncResult.documents` so `ConnectorsService.sync()` actually persists them — previously it only ever returned `documentsSynced: 0`. `listFiles`/`downloadFile`/`getFileMetadata`/`searchFiles` were also rewritten to be real (`downloadFile` previously always returned an empty buffer; `getFileMetadata` called an API with hardcoded-empty `owner`/`repo` so it always failed silently). While adding a mocked-Octokit test for this, discovered `@octokit/rest` was never in `package.json` — `GitHubAdapter.authenticate()` would throw `Cannot find module '@octokit/rest'` on first real use in any actual deployment, meaning the GitHub connector didn't just have a fake `syncAll`, it couldn't even authenticate. Checked the other lazy-`require()`'d adapter dependency and found the same problem: `googleapis` was also missing from `package.json` despite `GoogleDriveAdapter` requiring it. Installed both as real dependencies. While fixing Google Drive's dependency, also audited its `syncAll` and found the same *shape* of bug as GitHub's, just less obvious: it looked functional (called `downloadFile`/`getFileMetadata` per file, incremented `documentsSynced`) but never populated `SyncResult.documents`, so `ConnectorsService.sync()` took the branch that just counts a number — zero `Document`/`Chunk` rows were ever created, meaning a "successful" Google Drive sync added nothing to the knowledge base. Fixed to build real `ConnectorDocument[]` entries, including exporting Google-native Docs/Sheets/Slides to text/csv via `drive.files.export` (they have no raw bytes to download directly) and skipping folders, binaries, and non-exportable native types (Forms, Drawings, etc.) with an explicit `skipped` counter instead of silently miscounting them as successes. 16 new unit tests (9 GitHub, 7 Google Drive — neither adapter had any test coverage before); 204 unit tests green, clean typecheck/build/lint. README/ROADMAP updated: GitHub moved from "auth-only" back to fully shipped, Google Drive's description now notes native-format export. **Not yet done**: neither fix has been exercised against a real GitHub repo or Google Drive account — verified via mocked Octokit/googleapis only.
